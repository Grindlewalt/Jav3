# Install fixes (atomosserver fresh install, 2026-09-26)

Each entry: symptom / cause / fix / sha.

0. Pre-fix: `pacman -Sy --needed` (root phase + fix lines + bootstrap.sh) is an
   Arch partial upgrade. Fix: `pacman -S --needed`; on failure die with "run
   `sudo pacman -Syu` yourself, then re-run". 1f03022. (= PINCH #2)
0b. Pre-fix: port 8000 hard-coded (unit, verify, lan_port). Added `--port`
   (unit ExecStart, JARVIS_LAN_PORT in env, health check, printed URL) and a
   busy-port preflight. Service now starts even when root steps / BIOS are
   outstanding (web UI works without KVM). d027ee3. (= PINCH #4, #5 port part)
1. PINCH #1: second instance clobbers ~/.config/jarvis (foreign app there) and
   jarvis.service. Added `--name` (unit jarvis-<name>, config
   ~/.config/jarvis-<name>, JARVIS_INSTANCE_NAME=jav3-<name>) and `--config-dir`;
   backend/config.py reads JARVIS_CONFIG_DIR (env file, secrets.json,
   providers.json, backup.json); the unit sets it. Preflight refuses (CONFLICT,
   dies even with --yes) when the config dir holds another app's files, the unit
   name belongs to another checkout, or the port is taken. 38e0f0a.
4. PINCH #4: "not starting: root steps outstanding" when only BIOS is blocked.

   WARNING at startup when /dev/kvm or /dev/vhost-vsock is absent. 38e0f0a.
5. PINCH #5: setup URLs on :8000 — follows JARVIS_LAN_PORT written by --port
   (d027ee3); the installer prints every setup link, LAN IPs too (#18, 61a29e0).

   carries alt=<lan-ip:port> and `jav3 login` uses it only when a .local name
